③ 逐个对比

每张卡片取当前歌词行的前几个字当作一个「短语」，用同一时刻、同一套参数演出。每张卡片可以单独启停、切换新 / 旧实现，并单独覆盖速度（对应后端短语级的 pace，「跟随全曲」即为空）。底部黄条是该动效此刻的输出 o(t)。

④ 信号

时间轴以播放位置为中心（前后各 3 秒）。输入是基准脉冲串 x(t)（跟随节拍时为检测到的拍点，固定档时为等间隔网格，灰色竖线始终是检测到的拍点，便于看出固定档与音乐的漂移）；每个动效按自己的八度倍数 2n 取脉冲，经过自己的 h(t) 得到输出。

输入：起音强度 Õ(t) 与基准脉冲 x(t)
起音强度 Õ(t)检测到的拍点空档外推的补拍（虚线）基准脉冲 akδ(t−tk)
拍速估计：W(τ)·R(τ)
自相关 R(τ)加先验 W(τ)·R(τ)八度族（粗线为歌曲拍速）基准脉冲 τF
系统：各动效的冲激响应 he(t)
横轴 −0.6 ~ 1.8 s，竖线为 t = 0（拍点）。参数里的 Te = 2ne·Tb 取当前生效档位。
输出：各动效 oe(t) = Ge(t)·Me[(wexe * he)(t)]
竖线（短）为该动效实际使用的脉冲；关掉的卡片不显示。背景呼吸一栏的灰线是旧的实时检测（开启后记录），可以看到它比拍点晚。

⑤ 现有动效清单：哪些接入、哪些不接入

以代码里真实存在的动效为准（web/src/lib/lyrics/ 与 web/src/components/music-page/music-stage-effects.tsx）。判断标准：动效里有没有依据的周期或时长（现在拍长、扫动周期、抖动周期、呼吸周期都是拍脑袋的常数或按唱的时长均分），就适合换成节拍；动效是跟着唱的时间走的一次性语义过渡（唱完消散、唱完碎、由虚到实），就不接入，最多让时长随拍速缩放。

⑦ 公式

流程：音频 → 起音强度 → 拍速 T* 与拍点 → 基准脉冲（八度折叠到 τF）→ 每个动效按 2ne 取冲激串 xe(t) → 加窗 → 系统 he(t) → 输出 ye(t) → 门控与映射到 transform / text-shadow。分析部分（谱通量、自相关、八度族、动态规划）见 ../heartbeat-signal 原型的公式 1 ~ 3，这里不重复。

1. 基准脉冲与动效周期

Tb={τF=argmaxτ∈[0.5,1)sR(τ/2)+R(τ)+12R(2τ)跟随节拍0.52s,0.75s,1.00s快、中、慢,Te=2neTb

τF 是八度族在 60 ~ 120 次/分这一个八度里的代表，正好覆盖固定三档（60 / 80 / 115），所以「跟随节拍」与「固定档」可以无缝互换。ne 是每个动效固定的八度倍数（前端常量，不存后端）：心跳、放大、波浪、流光、背景 0，柔光、行点头、烟花 +1，抖动 −1，间奏圆点取使 Te 最接近 2 s 的 n。等价于心跳原型里的「目标心率」折叠，取 r0 = 60√2 ≈ 85 次/分时恰好 n = 0。

2. 输入：冲激串（两种来源，同一形式）

xe(t)=∑kakδ(t−tk(e)),{tk(e)∈Rkb+ne{ti},ak=amin+(1−amin)clamp(L(tk)−L10L95−L10)跟随节拍tk(e)=s+kTe,ak=1快 / 中 / 慢

{ti} 为动态规划得到的拍点（拍长 T*），kb = round(log2(τF/T*)) ∈ {−1, 0, 1}。重采样算子 𝓡m：m > 0 时每 2m 拍取 1 拍（逐级二分，每级取起音强度之和较大的那一组，通常是强拍），m < 0 时在相邻拍之间等分补拍（权重 0.85）。amin = 0.55：副歌更重、主歌更轻。空档（相邻拍距 > 1.5T*）先按 T* 外推补拍。

3. 输出：加窗 → 卷积 → 门控 → 映射

ye(t)=(wexe*he)(t+tlead)=∑tk∈Weakhe(t+tlead−tk),oe(t)=Ge(t)·Me[ye(t)]

分工：节拍决定「什么时候动」（x * h），歌词决定「哪里动、动多少」（窗 We 只保留短语唱的区间里的拍；门控 Ge 是原来的起落曲线或行高亮区间；强度 f 来自歌词标注）。短语里一拍都没有时取开唱后的第一拍，保证至少跳一次。拍点提前算好，所以 h 可以是非因果的（柔光在拍前就开始变亮，峰值正好落在拍上），播放时只对最近几拍求和。

5. 相位型：流光

φ(t)=k+t−tktk+1−tk,tk≤t<tk+1,c(t)=frac(φ)·(m+2)−1

φ(t) 是冲激串的「计数 + 线性插值」，即节拍相位；它不是卷积，但输入仍是同一个 x(t)，所以同样有四个档位。每遍正好一拍：拍速有轻微漂移时，光带也跟着变快变慢。

6. 交替阶跃：间奏圆点

s(t)=sk−1+(sk−sk−1)E(t−tk0.8Te),sk={1.2k 为奇数（吸）0.9k 为偶数（呼）

E 为 cubic-bezier(0, 0, 0.58, 1) 缓出（与 interlude.ts 相同）。等价于交替符号的冲激串经过「平滑阶跃」系统：每个拍点把目标在吸 / 呼之间翻转一次。

7. 点过程：离散事件类粒子

λ(t)=∑kNkδ(t−tk),Nk=max(1,⌊rTeAak+ck−1⌋)

r 为场景原来的生成速率（个/秒），A 为画面面积系数（同 stage-particles.ts），c 为累计的小数部分。长期平均速率与现在一致，只是从「均匀洒」变成「在拍点成簇出现」。

⑧ 后端数据结构建议（只给建议，不改代码）

后端已经有「特效节奏」字段：全曲 MusicLyricAnnotationsDto.Pace（编辑请求 MusicLyricAnnotationsEditReq.Pace，存储 lyricAnnotationData.Pace）与短语 MusicLyricAnnotationPhrase.Pace，取值 slow / fast，medium 为空不保存（lyricAnnotationPaces）。最小改动是沿用 pace，把枚举扩成四个值，不新增字段、不改表（标注本来就整体存在 lyric_annotations.data 的 JSON 里）。

接口里的样子 
{
  "status": "ready",
  "font": "song",
  "pace": "",            // 全曲：beat | fast | medium | slow
                         // 为空 = beat（新的默认，推荐）
  "lines": [{
    "text": "怦然心动的瞬间",
    "phrases": [{
      "text": "怦然心动",
      "effect": "heartbeat",
      "pace": "slow"     // 可选：短语覆盖，为空 = 跟随全曲
    }]
  }]
}
要点
粒度全曲级一个 pace（默认 beat）+ 短语级可选覆盖（现有能力，保留）。不按特效类型存：各特效相对基准脉冲的倍数 ne 是前端常量。
取值与存储全曲：beat 存空，medium / fast / slow 显式存（medium 以前不存，现在要存，因为空的含义变了）。短语：允许 beat / fast / medium / slow，与全曲相同时不存（沿用 phrase.Pace != data.Pace 的去重）。
不存的东西BPM、拍点、置信度都只在前端算、前端缓存；后端不需要音频分析能力。
兼容旧前端的 isLyricPace('beat') 为 false，会当作没有节奏 → medium，不会出错。
