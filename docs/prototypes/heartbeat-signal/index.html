① 选歌并分析

在浏览器里解码音频，从中提取节拍（输入信号），再经过「心脏」系统得到心跳曲线（输出信号）。分析只在本机进行，一首 4 分钟的歌约 1 ~ 2 秒。

② 效果对比

同一句歌词同时用旧、新两种心跳。旧的按这句唱的时长切分（约 0.75 秒一拍），和歌曲节奏无关；新的由歌曲节拍驱动，跳在拍子上，并随段落响度起伏。整句都按心跳渲染，方便在歌曲任意位置对比。

③ 信号

时间轴以播放位置为中心（前 3 秒、后 3 秒）。输入 x(t) 是节拍处的加权冲激；系统 h(t) 是一次「扑通-扑通」；输出 y(t) = x(t) * h(t)。

④ 参数

改参数立即生效（不需要重新分析音频）。目标心率决定「几拍跳一次」：快歌每两拍一跳，慢歌每拍一跳。

⑤ 公式

整个流程：音频 → 起音强度（输入特征）→ 拍速与节拍位置 → 心跳冲激串 x(t)（输入信号）→ 心脏系统 h(t) → 心跳强度 y(t)（输出信号）→ 缩放与辉光。

1. 起音强度（谱通量）

Xm[k]=∑n=0N−1w[n]s[mH+n]e−j2πkn/N,Ym[k]=ln(1+γ|Xm[k]|) O[m]=∑kmax(0,Ym[k]−Ym−1[k]),O~[m]=max(0,O[m]−O¯[m])σO

音频重采样到 fs = 11025 Hz 单声道；汉宁窗 N = 1024，帧移 H = 128，帧率 fr = fs/H ≈ 86.1 帧/秒；γ = 10。Ō[m] 为 0.4 秒滑动平均（去掉缓慢变化的部分），σO 为标准差。

2. 拍速（自相关 + 八度折叠）

R[τ]=1M−τ∑mO~[m]O~[m+τ],F(τ)=R(τ/2)+R(τ)+12R(2τ) τF=argmaxτ∈[0.5s,1s)F(τ),T*=argmaxτ∈{τF/2,τF,2τF}W(τ)R(τ),BPM=60T* W(τ)=exp(−12(log2τ0.5s)2)

真实拍长 T 的 2 倍（小节、强拍）与 1/2 倍（八分音符）也都强相关，所以先在 60 ~ 120 BPM 这一个八度里找「八度族」得分 F 最高的周期 τF，再在族成员中按 120 BPM 附近的感知先验 W 选出歌曲拍速。这样不会选到 3/2 这类非八度的误判（例：only my railgun 的自相关在 95.7 BPM 处也有峰，八度族得分会排除它）；而族内选 77 还是 154 只影响显示，心跳周期由下一步按目标心率从同一族中取。节拍置信度 c = R(T*) / R(0)。

3. 节拍位置（动态规划，允许拍速轻微漂移）

C[t]=O~[t]+maxτ∈[t−2T*,t−T*/2](C[τ]−α(lnt−τT*)2)

α = 100 控制「拍距尽量等于 T*」的强度；从末尾得分最高的帧回溯得到节拍帧 bi，节拍时刻 ti = (biH + N/2) / fs（取窗中心）。

4. 输入信号：心跳冲激串（按目标心率抽取节拍）

Th=τF·2n,n=round(log260/r0τF),rh=60Th∈[r02,2r0) x(t)=∑kakδ(t−tk),ak=amin+(1−amin)·clamp(L(tk)−L10L95−L10,0,1)

r0 为目标心率（默认 75，心率落在 53 ~ 106 次/分）。Th = 2k·T* 时：k = 1 每 2 拍取 1 拍（取起音强度之和较大的那一组，通常是强拍），k = −1 在两拍之间补一拍。L(t) 为 0.5 秒平滑的响度（dB），L10、L95 为全曲分位数，amin = 0.55：副歌跳得更重、主歌更轻。

5. 系统：心脏的冲激响应

g(t)=tτae1−t/τau(t),h(t)=g(t)+βg(t−Δ),Δ=clamp(κTh,0.14s,0.30s) H(s)=e/τa(s+1/τa)2(1+βe−sΔ)

g(t) 是临界阻尼二阶系统（双重极点 −1/τa）的冲激响应，在 t = τa 处达到峰值 1，是第一声「扑通」；再叠加一个延迟 Δ、增益 β 的回声，是第二声。默认 τa = 0.055 s，β = 0.65，κ = 0.3（第二声相隔约 0.3 个心跳周期，接近真实心音 S1、S2 的间隔）。

6. 输出信号与画面

y(t)=(x*h)(t)=∑kak[g(t−tk)+βg(t−tk−Δ)],Y(f)=X(f)H(j2πf) S(t)=1+Ay(t+tlead),G(t)=G0+By(t+tlead)

S 为字的缩放、G 为辉光强度（A = 0.16、B = 0.35，与现在心跳特效的幅度一致）。x(t) 的频谱是心率 rh 处的梳状谱线，乘上 H 后输出只保留低频的「扑通-扑通」形状，因此 y(t) 一定与歌曲节拍同周期、同相位。tlead（默认 20 ms）让画面略早于声音，抵消显示与音频输出的延迟。节拍是提前算好的，播放时只需对最近两三拍求和，开销可以忽略。

落地时的接入方式

分析首次播放某首歌时在 Web Worker 中跑 1 ~ 3 步，结果（拍速与节拍时刻）按歌曲缓存；用的是播放器已经拿到的音频，不增加下载
回退节拍置信度 c 过低（如纯钢琴、自由节奏）或音频不可解码时，回退到现在的「按唱的时长分拍」
替换word-effects.ts 的 heartbeatLevel 改为读取 y(t)，只在这句心跳歌词唱的区间内（加约一拍的余韵）生效，其余逻辑不变
