# 音乐播放器需求规格（Spec）

> 状态：方向已确定，待实现（2026-10-28）

## 1. 目标

实现 Apple Music 那样的歌词播放效果：逐字扫词、翻译与音译同屏、对唱与背景人声、流畅滚动与过渡动画，并给出一个完整可用的播放器页面（`/music`）。

交付范围就一个页面：`/music`。不扩张成音乐站。

参考实现：

- [amll-dev/applemusic-like-lyrics](https://github.com/amll-dev/applemusic-like-lyrics)：Web 端类 Apple Music 歌词组件的视觉效果与交互基准。
- [Mrs4s/StarryPlayer](https://github.com/Mrs4s/StarryPlayer)：歌词数据模型、多来源解析与对齐规则的工程基准。

### 1.1 参考原则：逻辑以 StarryPlayer 为准

- **逻辑层一律以 StarryPlayer 的代码逻辑为参考**：歌词解析与预处理、翻译 / 读音（音译）与主歌词的同步、歌词来源选择与缓存、当前行与高亮的判定（歌词展示策略）、播放队列与播放模式、进度时钟与会话恢复（播放策略）。设计或实现这些部分前，先查对应的 StarryPlayer 实现；行为有差异时以 StarryPlayer 为准，确需偏离的在本文档中注明原因。
- **界面与交互由我们自己设计**：功能与 StarryPlayer 大致对齐即可，界面外观、交互方式可以不同，并体现我们自己的风格（例如歌词来源标签用各平台自己的单色标志、歌单为右侧抽屉）。StarryPlayer 是 Swift 原生应用，其界面代码既不参考也无法复用；需要时只借鉴其动效表现（如弹簧、透明度、模糊的取值），用 DOM / CSS 自行实现。
- **许可证**：StarryPlayer 为 AGPL-3.0，本仓库为 MIT。只借鉴算法、规则与参数，按我们的数据结构自行实现；不复制、不逐行翻译其源代码，代码与注释中不出现其原文。

## 2. 歌词策略和歌词来源

### 2.1 总体策略

参照 StarryPlayer 的 `LyricsResolver`：歌词不按「谁先返回」决定，而是按**质量等级（tier）**决定，高等级胜出并原地执行升级；同一首歌只展示一份结果，不做逐行混拼。

优先级链（从高到低）：

1. **TTML**（逐字 + 翻译 + 音译 + 对唱 agent + 背景人声 + 段落，信息最全，一旦命中就整段胜出）。同一等级内再分两个子来源：**自定义 TTML 源**（优先，见 2.6）> **AMLL TTML DB**
2. **平台逐字歌词** —— 网易云 `yrc` / QQ `qrc` / 酷狗 `krc`，三家平级，按 2.3 的顺序尝试
3. **平台行级歌词** —— `lrc`，仅行时间，无逐字
4. 无歌词 —— 显示「暂无歌词」或纯音乐占位

硬规则：

- **优先逐字**：只要存在任一逐字来源，不得停留在行级。
- **只升不降**：允许先展示行级（快），TTML 到达后原地升级；升到 TTML 后不再回退。
- **宁缺勿错**：附加信息（翻译/音译）挂不上就丢弃，不用「最近一行」凑。

### 2.2 来源

| 来源 | 内容 | 获取方式 |
|---|---|---|
| 自定义 TTML 源（自建静态目录） | `.ttml`：同官方库，条目由自己维护 | `{url_prefix}/{ncm_song_id}.ttml` 直取，见 2.6 |
| AMLL TTML DB（`amll-dev/amll-ttml-db`） | `.ttml`：逐字、翻译、音译、对唱 agent、背景人声、段落 | 按平台 id 直取 `{platform}-lyrics/{id}.ttml`，多镜像，后端缓存 |
| 网易云音乐 | `yrc` / `ytlrc` / `yromalrc`（逐字），`lrc` / `tlyric` / `romalrc`（行级） | 已有 `internal/service/music.go` 的 `GetLyric` |
| QQ 音乐 | `qrc`（逐字），`lrc`（行级），翻译（LRC）/ 音译（QRC）随接口返回 | **已实现**：`internal/service/music_qq.go`，按 2.3 匹配，见 7.2a |
| 酷狗音乐 | `krc`（逐字），`lrc`（行级） | 待定（见第 10 节） |

> AMLL TTML DB 的实际布局（已核对）：`raw-lyrics/{时间戳}-{作者 id}-{hash}.ttml` 为原始文件，`{ncm,qq,am,spotify}-lyrics/{平台 id}.ttml` 为按平台 id 建立的同内容副本，另有 `metadata/raw-lyrics-index.jsonl`（每行 `{metadata, rawLyricFile}`）用于检索。**按 id 取词只需直取副本文件，不需要加载索引**（原来 2.3 的「必须缓存索引」结论作废）。

### 2.3 命中与匹配

- **自定义源**：最优先探测，URL 由配置的 `url_prefix` + 平台 id 固定拼接，命中规则见 2.6。
- **AMLL 官方库**：按歌曲在各平台的 id 直接拼 `{mirror}/{platform}-lyrics/{id}.ttml`，命中 200 即用（已实测 raw.githubusercontent / jsDelivr / `amlldb.bikonoo.com` 三个镜像均可用；不存在的 id 前两者返回 404，`amlldb.bikonoo.com` 约 5 秒后返回 302）。目前只有网易云 id，取 `ncm-lyrics/{id}.ttml`。
  - 偏离 StarryPlayer：StarryPlayer 只有一个镜像模板；我们**并发请求全部镜像**，任一命中即采用，其余取消；全部「确定未命中」才记负缓存。
- **平台侧**：有该平台 id 时直取；没有时用**标题 + 歌手 + 时长**打分匹配同一录音（当前音乐库只存了网易云 id，QQ / 酷狗的歌词要靠这一步才能用上）。匹配规则（同 StarryPlayer 的 `LyricCandidateMatcher`，`scoreLyricCandidate`）：
  - 归一化：小写，去掉空白、标点与符号。
  - 歌名须相同，或一方包含另一方且较短的一方不少于较长一方的 34%；时长都已知时相差不超过 20 秒，5 秒内为「时长接近」。
  - 有歌手时须有一位歌手相同或互相包含（至少 2 个字，候选的歌手按 `、&;，,/|·・` 拆分）；歌名不同时还须歌手匹配或时长接近。
  - 得分：歌名相同 10 / 包含 4，歌手相同 +5 / 包含 +2，专辑相同 +2，时长接近 +3；取最高分，同分取靠前的；没有合格的候选时视为没有匹配（宁缺勿错）。
- **平台尝试顺序**：歌曲所属平台优先，依次为 网易云 → QQ → 酷狗；第一个拿到逐字结果即停，三家都没有逐字时取第一家行级结果。
  - 实现：网易云与 TTML 并发请求；网易云到达后，若**不是逐字且 TTML 尚未命中**，再请求 QQ 音乐（同 StarryPlayer：TTML 已上屏或拿到逐字即停）；读者为这首歌固定了 QQ 音乐时一开始就请求。同一等级内网易云优先于 QQ 音乐。
  - 匹配到的 QQ 歌曲还会按 mid 查 AMLL TTML DB 的 `qq-lyrics/{mid}.ttml`（同 StarryPlayer：TTML DB 用各平台匹配到的 id 查询）；按网易云 id 收录的 TTML 优先。
- **确定未命中**：3xx（不跟随重定向）、404、410、正文不是 TTML（不以 `<` 开头、不是格式正确的 XML 或根元素不是 `tt`）。其余状态码、超时、网络错误为**出错**，不作为未命中缓存（同 StarryPlayer）。

### 2.4 升级与借补

- TTML 与平台歌词**并发请求**（前端同时请求 `/lyric` 与 `/lyric/ttml`）；等级 TTML > 平台逐字 > 平台逐行，**只升不降**：先到的先上屏，更高等级到达后原地替换（`lib/lyrics/resolve.ts`）。
- 防闪屏（同 StarryPlayer）：平台结果上屏前若 TTML 已到达，直接显示 TTML，不先闪一下平台歌词。
- TTML 命中但**缺翻译 / 缺音译**时，向平台歌词**借**，而不是因此改用平台歌词：按时间与 TTML 主唱行一对一挂载（宁缺勿错，容差 1 秒）；含中日韩文字的音译行不借（多为「以下音译由 AI 生成」之类的说明，同 StarryPlayer）。先向网易云借，网易云缺的那一种再向 QQ 音乐借。
- **去掉署名行**（同 StarryPlayer 的 `LyricsCreditStripper`，`lib/lyrics/strip-credits.ts`）：平台歌词首尾的「歌名 - 歌手」、「词：…」「作曲 : …」「Producer: …」、「未经许可不得翻唱」等；只去开头最多 16 行、结尾最多 8 行中连续的署名行，开头 3 行内单独的歌名或歌手行也去掉，不会把全部行去掉；TTML 不处理。
- QQ 音乐翻译中的 `//` 表示该行没有翻译，不挂载；QQ 音乐的纯音乐占位（「此歌曲为没有填词的纯音乐，请您欣赏」）按纯音乐处理。
- **按曲目固定来源（pin）**：读者可在歌词来源标签中为某首歌固定来源（存本地，最多 2000 首，超出淘汰最早的）；固定的来源没有歌词时回落到自动选择（同 StarryPlayer）。

### 2.5 缓存

参数同 StarryPlayer，后端进程内缓存（LRU），同一来源、同一 id 的并发请求合并：

| 内容 | 命中 | 确定未命中 | 出错 |
|---|---|---|---|
| TTML（自定义源、AMLL 分别缓存） | 长期（只受 LRU 淘汰） | 72 小时 | 不缓存 |
| 平台歌词（网易云） | 30 天 | 1 天（之后可能补上） | 不缓存 |
| 平台歌词（QQ 音乐，按网易云歌曲 id，含匹配结果） | 30 天 | 没有匹配或没有歌词 1 天 | 不缓存 |
| 按 QQ 歌曲 mid 收录的 AMLL TTML | 长期 | 72 小时 | 不缓存 |

### 2.6 自定义源（自建 TTML）

允许把自己整理好的 TTML 放到自有静态目录，作为一个与官方库同类型（AMLL/TTML）的歌词源，用来覆盖官方库未收录、或官方版本不满意的情况。

**定位**：

- 类型记为 `amll`（即 TTML 逐字格式），与官方库同一 tier，但**排在其前面**——同名先取自己的。
- 只做「按网易云歌曲 id 的覆盖」，不做跨平台 id 体系、不做搜索接口。

**寻址规则**：

```
{url_prefix}/{ncm_song_id}.ttml
```

- `url_prefix` 由后端配置项（环境变量）提供，例如 `https://static.example.com/ttml`，后端负责去尾斜杠后再拼接。
- 文件名固定为歌曲的网易云 id，扩展名固定 `.ttml`。
- 一个 id 只对应一个文件，**没有索引文件，没有元数据**，命中判断完全靠 HTTP 状态。

**判定与容错**：

- `200` 且响应体以 `<` 开头、能被 TTML 解析器成功解析 → 命中，作为最高优先级结果使用。
- `404` / 其他非 2xx / 网络错误 / 解析失败 → 视为未命中，静默回落到官方库，不向用户报错。
- 请求需设超时、限制响应体大小（防止误配置拉回整页 HTML），只接受配置好的 `url_prefix`，不接受任何来自前端的任意 URL（避免 SSRF）。
- 不做重定向跟随；重定向一律当未命中。

**缓存**：

- 命中内容长期缓存，按 id 存。
- 确定未命中做 72 小时负缓存（见 2.5），避免每次播放都去探一次；更新文件后需等负缓存过期或重启后端。

**与完整策略的关系**：

- 自定义源命中即整份采用，不与官方库或平台歌词逐行混拼；缺翻译/音译时按 2.4 向平台借。
- 自定义源与官方库的探测可以并发；自定义源命中后丢弃官方库结果。

## 3. 非目标

### 3.1 不做

- **不做多用户**：没有账号体系、没有云端歌单、没有收藏/喜欢/播放历史/播放次数，不对不同访客展示不同内容。
- **不做播放列表管理**：不做建歌单、拖拽排序、增删歌曲、导入导出。播放列表就是在后台配置好的那一份，前端只读展示与播放。
- **不做其他页面**：不做艺术家页、专辑页、平台搜索页、排行榜、歌词站、歌词编辑器。整个音乐功能只有 `/music` 一个页面。
- **不做音乐平台搜索**：不调任何外部音乐接口搜歌、不接平台榜单、不允许用户搜索库外歌曲。只允许对已配置好的播放列表做**前端本地过滤**（见 8.11）。
- **不引入 AMLL 运行时**：不依赖 `@applemusic-like-lyrics/*`（AGPL-3.0 与本仓库 MIT 不兼容），只借鉴其视觉参数与数据模型，自己实现。
- **不自建歌词库平台**：自定义 TTML 源只靠静态文件目录（见 2.6），不做上传界面、审核、版本管理、多人协作。
- **不做桌面/移动客户端**：只做 Web 页面，不做 Tauri / App / 后台常驻播放。

## 4. 术语

| 术语 | 含义 |
|---|---|
| 播放器页 | `/music`，本规格交付的唯一页面 |
| 悬浮播放器 | 现有的全站悬浮球 + 弹出面板（`components/common/music-player.tsx`），与播放器页共用同一份播放状态 |
| 歌单 | 后台配置好的唯一一份播放列表（网易云歌单或静态 JSON），前端只读 |
| 歌词舞台 | 播放器页中滚动展示歌词的区域，即第 8 节描述的渲染效果 |
| 行 / 词 | 一行歌词由若干带时间的词组成；词是逐字擦除的最小单位（中日文通常为单字，拉丁文为单词） |
| 行组 | 一行主歌词连同附着在它上方或下方的背景人声行 |
| 逐字歌词 / 行级歌词 | 有词级时间（TTML、yrc、qrc、krc）/ 只有行时间（lrc） |
| 翻译 / 音译 | 译文（`tlyric` 等）/ 读音，如日语罗马音（`romalrc` 等） |
| 对唱（duet） | TTML 中 agent 不是主唱的行，右对齐显示 |
| 背景人声（BG） | TTML 中标为背景的行，字号更小、附着在主行上 |
| 间奏 | 相邻两行之间 ≥ 7000ms 的空隙 |
| 来源等级（tier） | 歌词来源的质量等级，见 2.1；高等级胜出，只升不降 |
| 音频时钟 | 全局 `<audio>` 元素的 `currentTime`，是播放进度的唯一来源 |

## 5. 功能需求

### 5.1 页面形态

- `/music` 为**沉浸式全屏页面**：不套用站点顶栏、侧栏与页脚，背景为封面驱动的动态背景（8.10）；左上角保留一个返回按钮（返回上一页，没有上一页时回首页）。
- 进入播放器页时隐藏悬浮播放器，离开后恢复；进出页面不打断播放、不重置进度。
- **桌面端（≥ 1024px）**：左栏为封面、曲名 / 歌手 / 专辑、进度条与控制栏；右栏为歌词舞台；歌单为从右侧滑出的抽屉。
- **移动端（< 1024px）**：单栏，在「封面视图」与「歌词视图」之间切换（点击封面或歌词切换）；控制栏固定在底部；歌单为底部抽屉。
- 歌单为空或加载失败时显示空态，不渲染控制栏。

### 5.2 播放控制

- 播放 / 暂停、上一首、下一首、播放模式（列表循环 / 单曲循环 / 随机）、可拖动进度条、音量与静音。
- 键盘：空格播放 / 暂停，← / → 快退 / 快进 5 秒，↑ / ↓ 调节音量；焦点在输入框内时不响应。
- MediaSession（锁屏 / 控制中心）沿用全局播放器现有实现。
- 播放模式、音量、当前曲目与进度沿用现有的本地存储，与悬浮播放器共享。

### 5.3 歌词舞台

- 按第 8 节渲染；点击某一行跳转到该行开始播放；手动滚动期间暂停自动对齐，松手后回归（8.4）。
- **翻译与音译为两个独立开关**，可同时开启（同时开启时按 8.5 的顺序同时显示）；开关状态存本地，播放器页与悬浮播放器共用。
- 无歌词时显示「暂无歌词」；纯音乐显示纯音乐占位；歌词加载中显示骨架，行级结果先到先上屏，更高等级到达后原地升级（2.4）。

### 5.4 歌单面板

按 8.11：一次拉全、本地过滤、点击即播放、不改变队列；当前曲目在列表中高亮，打开面板时自动滚动到当前曲目。

### 5.5 悬浮播放器（播放器页的缩小版）

- 悬浮球（可拖动、贴边停靠）点开后是播放器页的缩小版：深色沉浸卡片，背景为模糊封面；封面、歌名、歌手与歌词来源标签，歌词舞台（同一歌词引擎的紧凑模式），控制栏（同一组件的紧凑模式）。
- 歌名与歌手（含专辑）超出宽度时以跑马灯滚动（悬停暂停，两端渐隐；减少动态效果时改为省略号截断）。
- 右上角按钮进入完整的播放器页 `/music`；歌单为从歌单按钮弹出的小浮层（含列表内搜索，点歌后收起，悬浮卡片保持打开），不使用播放器页的侧边抽屉。
- 紧凑模式只缩小字号、间距与间奏高度，焦点对齐位置为歌词区高度的 40%，按距离模糊减半；其余行为（逐字擦除、翻译与音译、点击跳转、手动滚动）与播放器页一致。
- 播放器页的歌名与歌手同样在过长时以跑马灯滚动。
- 播放时悬浮球以专辑主题色发光。文章内高单曲卡的歌词区同样使用紧凑模式，文字颜色跟随站点亮暗主题（`--lyric-color`）。

### 5.6 分享地址

- 播放器页的地址实时带上当前曲目与进度：`/music?id=网易云歌曲 id&start=开始秒数`，`start` 保留两位小数；播放中最多每秒更新一次，停下后写入最后的进度；用 `history.replaceState`，不产生历史记录；其他查询参数保留。
- 打开带参数的地址：歌曲在歌单内时定位到该曲目与进度（不自动播放，浏览器的自动播放限制）；不在歌单内时忽略参数。整页打开时由悬浮播放器的恢复逻辑处理，站内跳转时由播放器页处理。
- 本地存储的恢复策略不变：没有参数时仍按本地存储恢复上次的曲目与进度，播放中照常写入本地存储。

## 6. 非功能需求

### 6.1 性能

- **高频进度不进 React 状态**：播放进度不再放进 music context 的 value；只显示文字的地方（时间、进度条）订阅节流后的时钟（不高于 4 次/秒），歌词舞台在 `requestAnimationFrame` 中直接读音频时钟。
- music context 的 value 需 memo，播放进度变化不得引起全站使用 `useMusic()` 的组件重渲染。
- 歌词舞台逐帧动画只修改 `transform` / `opacity` / `filter` 与遮罩，不在逐帧路径上触发 React 渲染或布局（8.12）。
- 播放器页的代码（歌词引擎、TTML 解析）按路由拆分，不进入其他页面的包。
- 页面挂起后回归时单帧时间差钳制在 100ms（8.4）。

### 6.2 可访问性

- 所有控制有可读名称；进度条与音量为 slider 语义并可用键盘操作。
- `prefers-reduced-motion` 时关闭弹簧、模糊、词强调与阶梯入场，只保留整行高亮与瞬移滚动。
- 歌词文字与背景的对比度在最暗、最亮的封面配色下都需可读：动态背景之上统一加一层压暗遮罩。

### 6.3 可调参数

第 8 节标注「可调」的参数（羽化宽度、弹簧重量 / 刚度 / 阻尼、对齐锚点与位置、模糊上限、间奏阈值、提前起唱等）**集中定义为常量**（`web/src/lib/lyrics/config.ts`），不提供设置界面，也不进后台配置。

### 6.4 安全

- 自定义 TTML 源只接受环境变量中配置的前缀，不接受前端传入的任何地址；不跟随重定向，限制超时与响应体大小（2.6）。
- TTML 在前端用 `DOMParser` 以 `application/xml` 解析，只读取文本与时间属性，不把任何内容作为 HTML 插入页面。

### 6.5 兼容

- 不支持 `mix-blend-mode: plus-lighter` 时降级为单层高亮（8.2）；不支持 WebGL 时动态背景降级为 CSS 模糊封面。

## 7. 数据与接口

### 7.1 现有接口（沿用）

| 接口 | 用途 |
|---|---|
| `GET /api/v1/music/playlist` | 歌单曲目（含时长，静态歌单可无） |
| `GET /api/v1/music/song/:id/audio` | 播放地址，302 跳转到网易云临时地址 |
| `GET /api/v1/music/song/:id/lyric` | 网易云歌词（`lrc` / `tlyric` / `romalrc` / `yrc` / `ytlrc` / `yromalrc`），即平台等级的歌词 |

### 7.2 新增：TTML 歌词

`GET /api/v1/music/song/:id/lyric/ttml`（公开，`:id` 为网易云歌曲 id）

- 后端并发探测：自定义源 `{MUSIC_TTML_URL_PREFIX}/{id}.ttml` 与 AMLL TTML DB 全部镜像 `{mirror}/ncm-lyrics/{id}.ttml`；按优先级取第一个命中（自定义源优先，命中后不等 AMLL）。
- 可选参数 `source=custom|amll`：只取某一来源（供手动切换使用）；为空时自动选择。
- 命中：`200`，`{ "source": "custom" | "amll", "ttml": "<tt ...>...</tt>" }`；均未命中：`404`（`lyric_not_found`）。
- 后端只做探测、校验（以 `<` 开头、格式正确的 XML、根元素为 `tt`）与缓存，不把 TTML 转换为其他结构；解析在前端（`lib/lyrics/parse-ttml.ts`）。
- 配置：
  - `MUSIC_TTML_URL_PREFIX`（环境变量，可选）：自定义源前缀，未配置时跳过自定义源。
  - AMLL 镜像列表为后端常量（raw.githubusercontent / jsDelivr / `amlldb.bikonoo.com`）。
- 缓存见 2.5。单次请求超时 8 秒（同 StarryPlayer），响应体上限 1 MB，不跟随重定向。

### 7.2a 新增：QQ 音乐歌词

`GET /api/v1/music/song/:id/lyric/qq`（公开，`:id` 为网易云歌曲 id）

- 后端取网易云单曲信息（歌名、歌手、专辑、时长），以「歌名 歌手」调用 QQ 音乐公开搜索接口（`c.y.qq.com/soso/fcgi-bin/client_search_cp`，不需要签名），按 2.3 的规则选出同一首歌，再调用 `GetPlayLyricInfo` 取正文、翻译与音译。
- 该搜索接口会间歇性返回 500：失败时改用联想搜索（`smartbox_new.fcg`，只有 mid）+ 曲目详情（`CgiGetTrackInfo`，批量补上时长、专辑与歌手）。
- 正文与音译为十六进制密文：QQ 音乐客户端的三重 DES 变体（与标准 DES 有三处不同，见 `music_qrc.go`）解密后再 zlib 解压；QRC 去掉 XML 外壳（取第一个 `LyricContent` 属性，以 `"/>` 结束）。
- 返回：`200`，`{ "song_mid", "format": "qrc" | "lrc", "lyric", "translation", "romanization", "ttml"? }`；没有匹配且没有 TTML 时 `404`（`lyric_not_found`）；QQ 音乐接口出错时 `502`（`music_lyric_source_failed`）。解析在前端（`parseQqLyrics`）。
- 缓存见 2.5，同一首歌的并发请求合并；单次请求超时 10 秒。

### 7.2b 新增：歌词标注（大模型辅助）

`GET /api/v1/music/song/:id/lyric/annotations`（公开，`:id` 为网易云歌曲 id）

- 目的：补足浏览器分词的不足，并为强调特效（8.2）挑选值得强调的词句、特效类型、每行的情绪基调与副歌行。**标注只引用歌词原文，不含也不改变任何时间轴**；时间一律取自歌词本身。
- 懒处理：读者播放到某首歌（且开启了歌词特效、歌词是逐字的）时，前端才请求；还没有标注时后端开始生成并返回 `{ "status": "pending" }`，前端每 5 秒再取一次，最多等 3 分钟。
- 生成：用站点配置的大模型（与 AI 摘要相同的配置与全局并发限制），输入为带行号的歌词文本（网易云逐字 > 网易云逐行 > QQ 音乐，去掉时间标签，最多 150 行），要求只输出 JSON：`{"lines":[{"i":行号,"mood":"bright","chorus":true,"phrases":[{"text":"原文片段","effect":"swell","color":"gold"}]}]}`；`color` 可选，只用于带颜色联想的意象；`scene` 可选，为写到具体画面的行选择全屏粒子场景，全曲最多 4 处。
- 校验（不合格的条目一律丢弃）：行号必须存在；短语必须是该行原文的连续片段（忽略空白、标点与大小写）、最长 12 个字；每行最多 2 个短语，全曲短语总数不超过「行数 / 2 + 4」；情绪只能是 calm / bright / sad / intense，特效只能是 swell / glow / wave / shake / focus（未知的特效改为 swell），场景只能是 petals / sparks / snow / stars / bubbles / rain（未知的丢弃），颜色只能取 32 色语义化色板中的名称（如 starry-blue 星空蓝、violet 罗兰紫，定义在后端 `lyricAnnotationPalette`，名称、中文名与意象写进提示词，色值在前端 `lib/lyrics/colors.ts`；旧版 8 色名称映射到最接近的新颜色，未知的颜色丢弃）。同一文本的行合并为一条。
- 返回：`{ "status": "ready", "stale"?, "lines": [{ "text": 行原文, "mood"?, "chorus"?, "scene"?, "phrases": [{ "text", "effect", "color"? }] }] }`
- 演出：shake 演唱时字快速细微地抖动；focus 在高亮行内先模糊、唱到时变清晰。播放器页（`/music`）另有全屏特效（`MusicStageEffects`，信号计算见 `lib/lyrics/stage-effects.ts`）：唱到 swell / shake 时背景呼吸亮起，唱到带颜色的短语时背景泛起该颜色，`scene` 从标注行开始持续 8 行（或到下一个场景）全屏飘落粒子（`lib/lyrics/stage-particles.ts`）。悬浮播放器与文章内单曲卡只有字词级效果；关闭歌词特效或系统要求减少动态效果时全部不演出。；前端按行文本（归一化后）匹配到当前显示的歌词上，因此与歌词来源（TTML / QQ / 网易云）无关。
- 持久化：表 `lyric_annotations`，按「歌曲 id + 歌词文本 SHA-256」唯一；歌词文本变化后重新生成。
- 有效期：后台「AI」中配置（`lyric_annotation_ttl_days`，默认 7 天，1～365）。过期后接口仍返回旧结果并标记 `stale: true`，同时在后台重新生成，前端先用旧结果并继续轮询；生成成功后覆盖原记录（`created_at` 为本次生成时间），失败时继续使用旧结果，30 分钟后再试。
- 手动刷新：`POST /api/v1/music/song/:id/lyric/annotations/refresh`（仅管理员），立即重新生成并返回 `pending`；播放器页歌词来源标签旁有仅管理员可见的刷新按钮。叠加了标注时，歌词来源标签最前面显示 AI 标志。
- 限制：只为博客歌单内的歌曲生成（网易云歌单；静态歌单无法在后端校验，不提供），未配置大模型时返回 404（`lyric_annotations_unavailable`）；生成失败后 30 分钟内返回 404（`lyric_annotations_failed`），之后再请求会重试。

### 7.3 前端歌词数据模型

解析器（`ttml` / `yrc` / `lrc` 及翻译、音译）统一输出以下结构，再经过 8.8 的预处理后交给歌词引擎：

```ts
interface LyricWord {
  text: string
  start: number // 毫秒
  end: number
  romanWord?: string // 逐词音译（8.5）
  ruby?: { text: string, start: number, end: number }[] // 逐字注音（8.5）
}

interface LyricLine {
  words: LyricWord[]
  start: number
  end: number
  translation?: string
  romanization?: string
  isDuet: boolean // 对唱，右对齐
  isBackground: boolean // 背景人声，附着在上一主行
}

interface ResolvedLyrics {
  source: 'ttml-custom' | 'ttml-amll' | 'ncm-yrc' | 'ncm-lrc' | 'qq-qrc' | 'qq-lrc' | 'none'
  wordTimed: boolean
  lines: LyricLine[]
}
```

- 悬浮播放器与文章内单曲卡的歌词区已迁移到此模型（共用歌词引擎的紧凑模式）；导航栏与单曲卡标题处的单行歌词仍使用 `MusicLyricLine`，由 context 从最终选出的歌词转换（`toSingleLineLyrics`，只保留主唱行），与歌词舞台显示同一来源。
- 解析器、预处理与来源选择都是纯函数，放在 `web/src/lib/lyrics/`，用 vitest 覆盖。

### 7.4 状态层

- `MusicProvider` 仍挂在根布局，全站只有一个 `<audio>`，是播放状态的唯一来源；播放器页只是它的另一个视图。
- 拆分为：
  - **播放状态 context**：歌单、当前曲目、播放 / 暂停、模式、音量、解析后的歌词与翻译 / 音译开关，以及各种操作；value 做 memo。
  - **时钟订阅**：`useMusicClock(intervalMs)`，基于 `useSyncExternalStore`，供显示时间与进度条使用；歌词引擎通过 `getAudio()` 自行在 rAF 中读取。
- **当前歌词行**不放进 context value：与播放时钟一样是外部 store（`lyricCursor`），只在换行时通知，由 `useCurrentLyricIndex` / `useCurrentLyric` 订阅（导航栏单行歌词、单曲卡），换行不会让所有使用 `useMusic` 的组件重渲染；MediaSession 标题直接订阅当前行，最多每秒更新一次。
- 歌词获取（平台歌词 + TTML 并发、只升不降、QQ 音乐兜底）**全站统一**：`contexts/song-lyrics.ts` 按网易云歌曲 id 获取并缓存各来源（同一首歌只请求一次，最多缓存 100 首），按同一套规则（2.1～2.4）选出歌词。当前曲目由 `MusicProvider` 使用；文章内的歌词摘录（展示与编辑器选句）通过 `useSongLyrics(id)` 使用，并遵循读者为这首歌固定的来源。播放器页、悬浮播放器、导航栏单行歌词、单曲卡与歌词摘录因此总是显示同一来源的歌词（不会出现播放器是 AMLL 逐字、导航栏是网易云的情况）。
- 歌词摘录：作者手填的原歌词（LRC）优先；否则使用统一选出的在线歌词，快照文本与在线歌词对不上时只显示快照文本（宁缺勿错）。

## 8. 界面

### 8.0 页面与边界

- 唯一的音乐页面是 `/music`，一个沉浸式全屏播放器：播放控制 + 歌词舞台（布局见 5.1）。
- 播放列表内容**完全来自后台配置**，页面不提供任何增删改入口；列表只是给人看和点，本身不构成独立页面。
- 列表内提供**本地搜索框**：只过滤已加载的播放列表，不联网、不查任何音乐平台（见 8.11）。
- 不设艺术家页、专辑页、平台搜索页等入口；页内所有交互都围绕“当前这一首”展开。

### 8.1 歌词显示结构

一行歌词由四个渲染层组成，顺序固定：

1. 主歌词行（逐字/逐词）
2. 背景人声行（可选，可在主行上方或下方，见 8.6）
3. 翻译行（可选）
4. 音译行（可选）

硬规则：**翻译与音译是两个独立开关，不互斥**，同时开启时同时显示（见 5.3）；使用自己的字号、透明度，不挤占主行。

### 8.2 逐字扫词与强调

- **逐字擦除**：按当前行进度用遮罩从左向右揭示，边缘带羽化。羽化宽度以主字号倍数为单位：`0.5`（iPad 观感）/ `1.0`（Android 观感），不得为 0。
- **已唱提亮**：高亮行叠两层副本（亮层 `mix-blend-mode: plus-lighter`、暗层镂空），亮/暗 alpha 为 `1` / `0.4`；浏览器不支持时降级为单层。
- **词强调**（已实现，`lib/lyrics/emphasis.ts` 计算分组，引擎逐帧演出）：满足条件的词按字符逐个“辉光放大 + 上浮”。
  - 规则（同 StarryPlayer）：按**词**判断，一个词唱满 1 秒、且少于 8 个字（拉丁文字还须多于 1 个字母）时强调，强度 = (min(时长, 2 秒) − 1 秒) / 1 秒。中日文用浏览器的 `Intl.Segmenter` 分词，词由若干逐字音节组成。
  - 浏览器分词与苹果系统不同（例如「怦然心动」会被切成「怦然 / 心 / 动」），切不出的成语、短语由歌词标注（7.2b）补上：标注的短语唱满 0.6 秒即演出，强度至少 0.3，可指定特效类型；与标注短语重叠的规则词让位给标注。
  - 特效类型：`swell` 放大（最多 1.14 倍）+ 辉光 + 上浮，左右的字轻微外推；`glow` 只发光、几乎不放大，适合温柔伤感的词；`wave` 不发光、逐字波浪上浮，适合轻快的词。
  - 起落曲线参考 AMLL：前半程较快升到顶点、后半程缓缓回落；演出时长至少 1000ms，字与字错开（时长 / 2.5 / 字数），上浮比辉光提前 400ms、时长拉长 1.4 倍；行尾一组加强 1.3 倍，副歌行加强 1.2 倍；背景人声行的上浮幅度翻倍。
  - 情绪基调（来自标注）决定辉光颜色：平静偏蓝、明亮偏暖黄、伤感偏紫、激昂偏红，颜色很淡，只带一点色温。
  - 被强调的词四周留出 0.3em 内边距（负外边距抵消，不影响排版），擦除遮罩改用像素坐标，放大的字与辉光不被遮罩裁掉。
  - 「歌词特效」开关（控制栏，存本地，播放器页与悬浮播放器共用）；减少动态效果时始终关闭。
- **词上浮**：普通词在行内按时间轻微上浮，背景人声行位移为两倍。
- **非逐字歌词**（仅有行时间的 lrc）：不做擦除，只做整行亮度与滚动。

### 8.3 行状态

| 状态 | 表现 |
|---|---|
| 高亮（正在唱或刚唱完） | 不透明度 `0.85` |
| 普通行 | `1` |
| 非动态歌词（纯行级） | `0.2` |
| 已唱且开启“隐藏已唱行” | 接近 0（用极小值而非 0，避免浏览器跳帧优化） |
| 视口外（含 overscan 外） | 不渲染，不透明度 `0` |

- **模糊**：按距焦点的行距分档（`1 + 距离`），上限 5px；窄视口（≤ 1024px）乘以 `0.8`；焦点行与触摸拖动期间不模糊。
- **缩放**：当前行放大，由弹簧驱动（值为百分比，`100` = 原始尺寸）。
- **阶梯入场**：同帧内多行位移动画逐行递增延迟（基础 `0.05s`），越靠后以 `1/1.05` 递减，形成错落感。
- 切换布局原因（播放推进 / 用户拖动 / 滚轮 / 跳转 / 重建 / 尺寸变化 / 配置变化）需分别决定是否禁用阶梯、是否重置间奏动画、是否瞬移不走近弹簧。

### 8.4 滚动、对齐与交互

- **对齐锚点**：`top` / `center` / `bottom` 三选一，配合容器高度比例位置（默认居中，约 `0.35`，可调）。
- **弹簧位移**：默认启用物理弹簧（重量 `1`、刚度 `100`、阻尼 `10`，均可调）；关闭后退回 CSS transition（低配降级）。
- **预渲染**：视口外保留 300px overscan 用于预构建，进入后才能逐字擦除不断帧。
- **用户滚动**：支持触摸拖动、滚轮单步、松手惯性；拖动时纵向位移直接跟随（不经过弹簧），松手后回归自动对齐；手动滚动期间冻结对齐焦点，不跟随播放进度。
- **跳转检测**：进度突变时自动判定为 seek，重置间奏动画并使用瞬移策略；可关闭。
- **单帧上限**：页面挂起后回归的单帧时间差钳制在 100ms，避免动画以数秒时长冲过头。

### 8.5 翻译、音译与注音

- **主次顺序**：原文、音译（发音）、翻译。字号比例参考 StarryPlayer（原文 48、音译 28、翻译 22）：音译 `0.58em`、翻译 `0.46em`（均不小于 10px），翻译不透明度 `0.5`、整行音译 `0.65`；紧凑模式（悬浮播放器、单曲卡）参考其小尺寸（原文 28、音译与翻译 18），二者均为 `0.64em`。
- **逐字音译（注音行，已实现）**：音译能对齐到原文音节时（`LyricLine.romanizationWords`），显示在原文下方：被同一个音译词覆盖的连续音节组成一个注音单元，原文在上、音译在下居中对齐，单元宽度取两者中较宽的一个；音译的每一段按所在音节的时间与原文同步擦除。对不齐时整行显示在原文之下、翻译之上。
- **对齐规则**（参考 StarryPlayer 的 `LyricRomanizationAligner`，`lib/lyrics/romanization.ts`，宁缺勿错）：
  - 来源自带逐字时间的音译（QQ 音乐的音译 QRC）直接使用，按开始时间归到原文音节。
  - 纯汉字行（拼音、粤拼）：有内容的音节与音译词数量相同、且每个音节只有一个字时一一配对。
  - 含假名的行（日文）：假名与拉丁文字音节的读音（wanakana，含は / へ / を、づ / ぢ、长音的常见写法）作为锚点在音译字母中依次查找；锚点之间的字母按音拍分给其间的汉字音节（浏览器拿不到汉字读音；促音留下的单个辅音不单独算一拍）；多出的字母并入前一个音节。锚点找不到、或汉字分不到音拍时视为对不齐。
  - 纯拉丁文字、韩文等不对齐。
- **逐字注音（ruby，TTML 的注音音节）**：未实现。

### 8.6 对唱、背景人声与多行重叠

- **对唱（duet）**：该行改为右对齐，`transform-origin` 置于右侧；间奏点若紧接对唱行，跟随右对齐。
- **背景人声（BG）**：
  - 字号 `0.7em`（可调，最小 10px），不透明度 `0.4`
  - 与所在主行组成一个“行组”，附着在主行上方或下方（可配置为始终在主行下方）
  - 激活时从 ± 80px 弹簧滑入，缩放从 `0.8` 过渡到 `1.0`；未激活时折叠隐藏
  - 一行主歌词下方最多一个背景人声行；背景行可自带翻译与音译
  - 背景人声的时间需与主行同步
- **多行重叠 / 合唱**：高亮是一个集合而非单值；一行唱完不立即熄灭，会与后面重叠的行一起保持高亮；句间空隙内上一行继续保持高亮以维持可读性。
- **无意重叠清洗**：重叠达到 500ms 视为有意（保留）；不足 100ms 或不足下一行时长的 10% 时视为无意，把上一行结束时间截断到下一行开始。

### 8.7 间奏与底栏

- **间奏**：相邻歌词行的空隙 ≥ 7000ms 时判定为间奏，在空隙处显示三个呼吸圆点；间奏期间清空歌词高亮、把焦点交给间奏点，并与弹簧、缩放、透明度联动。
- **底栏**：歌词最底部固定一行（可插入任意内容，如制作信息、版权），默认不透明度 `0.2`，聚焦时 `0.85`；曲末聚焦底栏。

### 8.8 歌词预处理

解析后、渲染前统一过一遍优化：

- 归一化连续空格
- 行级时间戳补齐为字级时间戳
- 主行与背景人声时间同步
- 清洗无意重叠（规则见 8.6）
- **提前起唱**：最多提前 600ms，且与上一行没有重叠时最多提前到上一行结束（只用掉句间空隙；快歌里紧挨着的短行若都提前 600ms，会被提前到同一时刻、同时高亮，焦点停在最早的一行）；与上一行重叠时提前 400ms，重叠不足 400ms 则提前重叠时长的 70%

### 8.9 不雅用语打码

支持三种模式：不处理 / 全遮 / 保留首尾。遮罩字符可配（默认 `*`）。

### 8.10 动态背景

封面驱动的流体背景，从封面图提取调色板后渲染。参考实现提供三种渲染器（网格渐变 / Titanium / 隔离色块），均为 WebGL 着色器。第一期先用放大模糊的封面 + 压暗遮罩（CSS），WebGL 实现放在第四期，载体待定（见第 10 节）。

### 8.11 播放列表面板与列表内搜索

播放列表面板承担两件事：看当前列表、在当前列表内快速找歌。

- **数据来源**：后台配置好的完整列表，一次拉全，前端本地持有；不做分页请求、不做增量同步。
- **搜索范围**：仅当前这份列表，**不联网**，不调网易云 / QQ / 酷狗 等任何外部接口，不允许搜到列表外的歌。
- **可搜索的字段**：歌名、别名（网易云的别名与译名）、艺术家、专辑、歌曲 id；歌词等需要另行请求的内容不参与。
- **匹配方式**（`playlist-filter.ts`）：统一全半角与大小写，忽略空白、标点与符号，平假名与片假名视为相同；多关键词用空格分隔，全部命中才算命中（可分别命中不同字段）。
- **排序**：按相关度：歌名 > 别名 > 艺术家 > 专辑，字段与关键词完全相同、以关键词开头时加分，关键词是歌曲 id 时置顶；同分保持歌单顺序。悬浮播放器的小歌单与播放器页的抽屉共用同一套搜索。
- **交互**：输入即过滤，本地内存操作不防抖；无结果时显示空态文案；清空输入框恢复完整列表；结果项点击即播放该曲。
- **不影响队列**：搜索只是视图过滤，不改变原列表顺序、不改变上一首/下一首的取曲顺序，也不清空当前播放。
- 当前正在播放的那一首被过滤掉时**播放不受影响**，仅从列表视图隐藏。

### 8.12 性能约束

- 视口外不渲染、不跑动画
- 高亮提亮所需的双层副本仅在焦点前后 2 行范围内保留
- 行级延迟构建：进入可视区（含 overscan）才创建具体行内容
- 优先使用 `transform` / `opacity` / `filter`，避免触发布局

## 9. 分阶段计划

每期结束时页面都完整可用，可以单独上线。

### 第一期：可用的播放器页

- 状态层拆分（7.4）：context value memo，进度改为时钟订阅；顺带消除现有组件每秒约 8 次的重渲染。
- 翻译、音译改为两个独立开关（5.3），悬浮播放器同步调整。
- 沉浸式页面骨架（5.1）：桌面双栏 / 移动端切换视图、返回按钮、进入时隐藏悬浮播放器。
- 播放控制与键盘操作（5.2），歌单抽屉与本地搜索（5.4、8.11）。
- 歌词舞台基础版：沿用现有网易云 yrc / lrc 解析，整行高亮 + 平滑滚动 + 点击跳转。
- 动态背景基础版：放大模糊的封面 + 压暗遮罩（CSS）。

**完成标准**：`/music` 可完整播放歌单，与悬浮播放器状态无缝衔接；切换页面不中断播放。

### 第二期：歌词引擎

- 新数据模型与解析器、8.8 预处理（7.3）。
- 歌词引擎核心（纯 TS 类 + React 包装）：弹簧滚动与对齐（8.4）、行状态与按距离模糊（8.3）、带羽化的逐字擦除（8.2）、翻译与音译（8.5）、手动滚动与惯性、跳转检测、间奏圆点与底栏（8.7）、阶梯入场。
- 视口外不渲染、延迟构建行内容（8.12）。
- 悬浮播放器与文章内音乐组件迁移到新数据模型。

**完成标准**：网易云逐字歌词在播放器页达到接近 Apple Music 的观感；低配设备上滚动不掉帧。

### 第三期：TTML

- 后端 TTML 接口（7.2）：自定义源 + AMLL 镜像、并发探测、正负缓存、SSRF 与大小限制。

**完成标准**：AMLL 库收录或自建源中存在的歌曲显示完整 TTML 效果；未收录的歌曲表现与第二期一致。
