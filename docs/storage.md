# 文件存储与迁移

## 1. 稳定链接

站内文件在正文、封面、头像、站点配置中一律保存为稳定链接 `/api/v1/file/f/<id>`（上传接口返回的 `url` 也是它）。链接只认文件 ID，不含存储信息：

- 文件换存储只改 `files.provider_id`，文章和页面无需改动；
- 修改 S3 的公开地址后，所有内容立即按新地址展示。

后端的 `middleware.UseFileLinks` 在两个方向上做转换：

| 方向 | 处理 |
| --- | --- |
| GET 返回的 JSON | 稳定链接改写为直链（仅限可直连的存储），浏览器直接向存储请求 |
| POST / PUT / PATCH 提交的 JSON | 存储直链还原为稳定链接（编辑器拿到的是直链，保存时会自动还原） |

## 2. 直连与代理

| 存储 | 访问方式 |
| --- | --- |
| S3，配置了 Base URL | 直连：图片由浏览器直接从 Base URL 加载，不经过本站后端，也不经过 Next 图片优化 |
| S3，未配置 Base URL | 代理：预签名链接会过期，只能经后端读取 |
| 本地、WebDAV | 代理 |

直连时不要把 S3 的域名加入 `NEXT_PUBLIC_IMAGE_OPTIMIZE_HOSTS`，否则 Next 会经本站服务器转一遍图片，占用源站带宽。

## 3. 迁移

迁移入口在控制台：

- 「存储供应商」页：迁移整个存储（文件 + HTML 页面版本）；
- 「文件」页：管理员勾选文件后点「迁移所选」。

迁移在后台执行，同一时间只运行一个任务。进度保存在共享状态中，多副本时任意实例都能查看。

执行步骤：

1. 把源存储遗留在内容中的旧直链（正文、草稿、封面、背景、头像、评论、历史版本、OIDC 图标、站点配置）还原为稳定链接。
2. 逐个复制存储对象（相同内容的文件共用一个对象），校验大小后修改文件记录的存储；目标中已有同样的对象时跳过复制。
3. 迁移整个存储时，再复制 HTML 页面各版本的文件。

源存储中的对象不会删除。中途失败、取消或实例退出后，重新发起迁移即可从剩余部分继续。

## 4. 保护规则

- 仍有文件或 HTML 页面版本的存储不能删除。
- 有文件的存储不能修改存放位置：类型、目录、Bucket、Prefix、WebDAV 地址。需要换位置时，新建一个存储并迁移过去。
- 名称、凭证、区域、端点、Path Style、Base URL 可以随时修改。修改 Base URL 前，后端会先把内容中按旧地址保存的直链还原为稳定链接。
- 迁移中的源存储和目标存储不能修改或删除。

接口（管理员）：

- `POST /api/v1/file/migration`：`{source_provider_id}` 或 `{file_ids}`，加上 `target_provider_id`
- `GET /api/v1/file/migration`：查询进度
- `POST /api/v1/file/migration/cancel`：取消迁移
- `GET /api/v1/file/provider-list`：返回值中的 `usage` 为各存储的占用情况
