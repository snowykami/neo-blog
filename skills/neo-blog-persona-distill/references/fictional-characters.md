# 蒸馏虚拟人物

适用于动画、漫画、游戏、小说、影视作品里的角色，以及虚拟主播等虚构人物。流程和真人一样（问清楚 → 采集 → 分析 → 生成 → 校验），区别在于素材从哪来、冲突时听谁的。

## 先问清楚

- **作品和角色**：作品名、角色名。
- **以哪个版本为准**：原作小说、动画、游戏、舞台剧里同一个角色的性格可能不一样。
- **以剧情的哪个阶段为准**：角色会成长，例如「第二季之后」「某个结局之后」。
- **是否采用社区二创设定**，采用哪些：用户提供的设定文档，或者社区公认、广泛流传的「民间设定」。不说就只用官方设定。
- **虚拟主播**：只用角色设定和直播、动态中以角色身份说的话，不涉及背后真人的身份和私事。

## 素材与优先级

从高到低，冲突时以优先级高的为准：

1. **官方设定**：官方设定集、公式书、官网与官方社交账号的角色介绍、作者访谈中对角色的说明。
2. **剧情**：角色在原作中做了什么、和谁是什么关系、怎么成长。行为比旁白和其他角色的评价更能说明性格。
3. **台词**：原作文本、剧本、动画字幕、游戏剧情文本和语音台词（游戏百科常整理成表）。台词是说话方式的主要依据。
4. **社区二创设定**（用户同意时才用）：只采纳大多数同人作品都在用的设定，个别作品的私设不用；和官方设定冲突时以官方为准，除非用户明确要用二创版本。明显恶搞、成人向或带攻击性的二创不用。

整理方式：

- 萌娘百科、Fandom、游戏 wiki 这类站点是社区整理的，可以用来找台词和设定要点，但尽量追到原作出处（章节、集数、任务名）。找不到出处的说法当作二创处理。
- 台词整理到 `corpus/canon.txt`，每行一条，台词和出处之间用一个制表符隔开（例如 `我才不是因为担心你呢！<TAB>第 3 集`）；二创设定整理到 `corpus/fanon.md`，注明来源。
- 报告里每条结论标明依据是官方设定、剧情、台词还是二创。

## 分析时的不同

- **说话方式**：去掉出处后用 `scripts/style_stats.py` 统计台词：

  ```bash
  cut -f1 distill-<id>/corpus/canon.txt > distill-<id>/corpus/self.txt
  python3 scripts/style_stats.py distill-<id>/corpus/self.txt
  ```

  重点看：
  - 第一人称和称呼（「本小姐」「吾」「前辈」）；
  - 口癖和句尾（翻译作品用通行译本的写法），并写明频率；
  - 语气（敬语、中二、毒舌）。
- **性格**：以剧情中的行为为主。注意角色在不同对象面前的差别（对朋友和对敌人说话不一样），选在博客评论区最自然的那一面。
- **兴趣与专长**：从设定里的爱好、职业、能力映射到真实世界的话题。例如精通机械的角色，`interests` 可以写机械、模型。作品里虚构的东西（魔法、虚构的国家和科技）不要写进 `expertise`，以免 AI 在真实话题上编造。
- **作息**：没有时间戳可以统计，按设定和剧情推断（学生、上班族、夜行性），时区按故事发生的地方定，见 SKILL.md 和 file-format.md 中关于时区的说明。

## 生成导入文件时

- `persona` 用角色的第一人称写，并说明出自哪部作品（例如「我是《某作品》里的某某」）。
  - 保持角色口吻，但角色读的是真实世界的博客文章：可以用角色的视角和价值观来评论，不要把作品里的虚构事件当成真实发生的事来讲。
  - 不要剧透，可以把「剧透」写进 `blocked_topics`。
- `style_samples` 用角色口吻新写，不整段照搬原作台词；可以化用口癖，原台词只在报告里少量引用作为证据。
- **头像**：官方立绘、截图受版权保护，不要默认拿来当头像。用用户有权使用的图片（自己画的、取得授权的同人图），或者留空，导入后在控制台选择。
- `username`、`nickname` 可以用角色名，和站内已有用户重名时加后缀。
- 虚拟人物不涉及本人同意的问题，但要尊重作品版权和原作者对角色的设定，不要让角色说出明显违背设定、损害原作形象的话。
