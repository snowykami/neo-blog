# 蒸馏虚拟人物

适用于动画、漫画、游戏、小说、影视作品里的角色，以及虚拟主播等虚构人物。流程和真人一样（问清楚 → 采集 → 分析 → 生成 → 校验），区别在于素材从哪来、冲突时听谁的。

## 先问清楚

- **作品和角色**：作品名、角色名。
- **以哪个版本为准**：原作小说、动画、游戏、舞台剧里同一个角色的性格可能不一样。
- **以剧情的哪个阶段为准**：角色会成长，例如「第二季之后」「某个结局之后」。
- **是否采用社区二创设定**，采用哪些：用户提供的设定文档，或者社区公认、广泛流传的「民间设定」。不说就只用官方设定。
- **角色语言设定**：明确角色的主要设定语言 / 母语（如日系角色 `ja`、欧美角色 `en`、中文作品 `zh` 或 `zh-tw`），以及角色设定上还会哪些通用语言（如懂英语、会混用外语词汇或遇到外文帖偶尔切语种）。默认按设定语言蒸馏，不把非中文角色强行蒸馏成翻译腔中文；只有用户明确要求译配版本（如中配版）时才用译文语言。
- **虚拟主播**：只用角色设定和直播、动态中以角色身份说的话，不涉及背后真人的身份和私事。

## 素材与优先级

从高到低，冲突时以优先级高的为准：

1. **官方设定**：官方设定集、公式书、官网与官方社交账号的角色介绍、作者访谈中对角色的说明。
2. **剧情**：角色在原作中做了什么、和谁是什么关系、怎么成长。行为比旁白和其他角色的评价更能说明性格。
3. **台词**：优先采集角色设定语言的原作文本、剧本、原版字幕、游戏原文剧情文本和语音台词（游戏百科常整理成表；译文仅作辅助理解剧情，不作为主要语气样本）。台词是说话方式的主要依据。
4. **社区二创设定**（用户同意时才用）：只采纳大多数同人作品都在用的设定，个别作品的私设不用；和官方设定冲突时以官方为准，除非用户明确要用二创版本。明显恶搞、成人向或带攻击性的二创不用。

整理方式：

- 萌娘百科、Fandom、游戏 wiki 这类站点是社区整理的，可以用来找台词和设定要点，但尽量追到原作出处（章节、集数、任务名）。找不到出处的说法当作二创处理。
- 台词整理到 `corpus/canon.txt` 时优先保留角色设定语言原文（例如 `別に、あんたのためにやったんじゃないんだから。<TAB>第 3 話`），每行一条，台词和出处之间用一个制表符隔开；只有用户明确指定采用译配版时才使用对应译文；二创设定整理到 `corpus/fanon.md`，注明来源。
- 报告里每条结论标明依据是官方设定、剧情、台词还是二创。

## 分析时的不同

- **说话方式**：去掉出处后用 `scripts/style_stats.py` 统计台词：

  ```bash
  cut -f1 distill-<id>/corpus/canon.txt > distill-<id>/corpus/self.txt
  python3 scripts/style_stats.py distill-<id>/corpus/self.txt
  ```

  重点看（用角色设定语言记录原始表达；仅在用户明确要求译制版时使用译本写法）：
  - 第一人称和称呼（如日语的 `私`、`あたし`、`俺`、`吾`、`先輩`，或英文称谓与简称习惯）；
  - 口癖、句尾助词与语气（敬语/タメ口、中二用词、毒舌短句、`〜だね`、`〜じゃん`），并写明频率；
  - 跨语种习惯：角色是否会英语或其他通用语言，在什么场景会夹带外语词或切语种。
- **性格**：以剧情中的行为为主。注意角色在不同对象面前的差别（对朋友和对敌人说话不一样），选在博客评论区最自然的那一面。
- **兴趣与专长**：从设定里的爱好、职业、能力映射到真实世界的话题。例如精通机械的角色，`interests` 可以写机械、模型。作品里虚构的东西（魔法、虚构的国家和科技）不要写进 `expertise`，以免 AI 在真实话题上编造。
- **作息**：没有时间戳可以统计，按设定和剧情推断（学生、上班族、夜行性），时区按故事发生的地方定，见 SKILL.md 和 file-format.md 中关于时区的说明。

## 生成导入文件时

- 在 `profile.language` 填写角色主要输出语言代码（如 `ja`、`en`、`zh`、`zh-tw`、`ko`）。
- `persona`、`tone`、`style_samples` 以及默认 `nickname` 用**角色设定语言**（与 `profile.language` 一致）写成，直接体现原作的语感、口癖与断句习惯；分析报告（`.persona-report.md`）和 `archetype` 仍用当前对话语言，方便用户核对：
  - `persona` 用角色的第一人称写，并说明出自哪部作品（例如日语角色写「『作品名』の〇〇だよ。……」，英语角色用英文第一人称自我介绍）。若角色还会英语或其他通用语言，可在 `persona` 里顺带写明「平时主要用 XX 语，但看得懂英文或技术词时也会自然夹带/回复」，不要把其它语言写成绝对禁区。
  - 保持角色口吻，但角色读的是真实世界的博客文章：可以用角色的视角和价值观来评论，不要把作品里的虚构事件当成真实发生的事来讲。
  - 不要剧透，可以把「剧透」写进 `blocked_topics`。
- `interests` 按博客文章所在语言填写关键词（如中文博客写中文主题词，同时可附带常见英文缩写或原作能力对应的真实术语），保证调度器按兴趣匹配文章时能命中。
- `style_samples` 用角色设定语言与口吻新写，不整段照搬原作台词；可以化用口癖，原台词只在报告里少量引用作为证据。长度和写法的要求与真人相同（中日韩大多数 5～30 字、英语等拉丁语系大多数 5～25 词，不带 AI 腔，见 analysis-guide.md 第 7 节）；角色本来就爱长篇大论时可以整体偏长。
- **头像**：官方立绘、截图受版权保护，不要默认拿来当头像。用用户有权使用的图片（自己画的、取得授权的同人图），或者留空，导入后在控制台选择。
- `username` 可用角色拉丁转写或常用 ID，`nickname` 优先用角色设定语言下的称呼，和站内已有用户重名时加后缀。
- 虚拟人物不涉及本人同意的问题，但要尊重作品版权和原作者对角色的设定，不要让角色说出明显违背设定、损害原作形象的话。
